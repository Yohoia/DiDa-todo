## 第一阶段

### AI 与人工协作

现有 AI 弹窗标题简化为「AI 整理」，使用轻量线性图标，不显示标题说明、顶部提示栏或来源标识；待办勾选沿用圆形金色样式，应用按钮仅显示「应用」。每条待办右侧提供线性铅笔图标，点击打开右侧详情抽屉：标题、描述、时间、清单、标签、优先级、预估、重复、提醒、锁定和子任务。普通任务详情和 AI 整理直接共用完整的 `TaskDetailForm`，包含头部 One Thing/锁定、标题/描述、重复、日期/时间、优先级、清单、标签、预计时长、提醒、子任务及底部操作；删除原独立精简编辑器，`OrganizationTaskDetail` 仅适配草稿状态和抽屉。整理弹窗锁定任务日期，只调整当天时间；设为「随时」可清空 AI 或原任务的时间。人工可选择 Inbox。AI 不猜时间的规则不限制人工输入。

每条内部保留原建议，可恢复原建议及原任务内容，不再展示「AI 建议 / 人工已调整」文字。所有编辑都只是弹窗草稿，只有最终确认的勾选项被写入。保存中禁止重复提交和关闭。标题必须非空、最多 200 字符；描述最多 50 字符且可清空。预估为 1–16 个番茄钟，标签最多 3 个、单个最多 12 字符，时间必须有效。

编辑抽屉确认只更新对应草稿；取消、关闭或 Escape 丢弃该次编辑，不关闭外层整理结果。使用合成数据实查取消、确认、标题/描述编辑、空标题校验、标签失焦提交、设为随时、切换清单、勾选与应用、Escape 和恢复 AI；实际任务详情仅查看，不修改数据。新增回归验证共享表单、确认前不写入、内容与元信息一并保存、标题同步时间轴标签、陈旧草稿拒绝与固定日期边界。

现有本地快照检查与云端条件更新继续生效，陈旧建议不能覆盖已改动、改期、完成或删除的任务。AI 仍仅处理日历所选那一天的未完成任务。

完整详情的草稿模式：日期可见但不可改期，时间仍可编辑；One Thing（跨任务唯一状态）、删除和开始专注显示但禁用，需先应用后在普通详情执行。重复沿用数据库能力开关。提醒、重复清除、锁定与子任务可暂存并一同应用，恢复 AI 建议也会撤销这些草稿改动。子任务沿用普通详情的 upsert/清理流程，非任务与子任务的跨表单事务；子任务写入失败会报失败，不能视为整项原子保存，可能已保存的任务字段需复查。涉及完整细节编辑时，应用前同时检查本地/云端提醒、重复、锁定和子任务快照。

### 重复与未安排排序

每日、每周或每 1–365 天重复，默认不重复。完成一个实例时，由数据库事务创建唯一后继；回滚或再次完成不生成第二份。

- 下一日期沿原日期的间隔推进，跳过已经过去或属于今天的日期，取第一个未来日期；无日期以应用当天为起点。固定 Asia/Shanghai。
- 继承标题、描述、清单、标签、优先级、预估、钟点、时长、提醒和重复间隔；克隆子任务并重置完成状态。
- 不继承完成状态、One Thing、锁定。每个实例有新身份和独立通知。
- 修改当前实例规则不回写历史或已经生成的后继；要修改后继请编辑后继实例。没有整条重复链批量编辑入口。
- 删除当前实例不会自动删除其他实例；取消重复作用于当前/未来待完成实例，不自动清除已经生成的后继。

迁移新增 `0007_repeating_tasks.sql`，不修改已执行迁移。旧数据库自动禁用重复设置，并说明升级要求；服务故障不能被当作「未部署」。`d0030e5` 触发的 CI run #34 已成功执行生产迁移作业，但还需在目标环境完成重复功能验收。

收件箱按日期浏览，不提供清单、标签和状态筛选下拉菜单。未安排事项按优先级、创建时间排列；不新建清单页，不强制改日期。

### 文字与语音录入

沿用原有「记一笔」和语音入口，不设置额外右上角按钮或 N 快捷键。普通创建无需 AI；支持明确的今天/明天/后天、today/tomorrow、YYYY-MM-DD、HH:mm、上午/下午几点及 am/pm，并显示预览。语音多事项从原有「逐项调整」进入共用确认列表，不额外增加文字多事项入口。

收件箱「记一笔」仍默认今天，明确日期覆盖默认，保存成功才显示回执。全局录入没有隐含今天。

文字多事项解析复用现有登录、同源、限流保护的解析接口；语音「逐项调整」复用同一确认列表。可改标题、日期、时间与清单，勾选后确认；取消未提交草稿不保存。不为此次文字录入采集音频。

2026-09-17 复查修复两处明确时间解析：中文时段 + 数字时间（如「下午3:30」）现按时段换算为 15:30 并连同时段前缀一起移出标题；「晚上12点」解析为 00:00，中午/下午 12 点仍按正午 12:00 处理。预览与回归均覆盖这些组合。

批量保存逐项报告结果，成功项移出草稿，失败项使用原 ID 重试。创建重试不插入重复任务，也不覆盖已存在任务的内容；若此前不确定的请求实际已经成功，后续内容修改请使用任务详情。语音历史只记录成功创建的事项。

## 第二阶段已实现：专注周期

每轮专注沿用当前偏好时长；短休息 5 分钟，每完成 4 轮长休息 15 分钟。可自动开始休息；本次计时可勾选休息结束自动开始下一轮，也可手动跳过休息。自动下一轮不是新的全局偏好。

当前标签页 sessionStorage 按账号保存阶段、剩余时间、截止时刻、暂停状态、轮次与当前记录 ID；不同标签页不共享活动时钟。刷新后未暂停的计时继续走，暂停期间不计入时长。离开很久只结算当时的一轮，不凭空补出多个番茄钟。

到零先保存专注事实再切换阶段；每轮使用新 ID，检查点沿用本轮 ID，云端幂等追加时长。休息不生成专注记录。关闭、Esc 或「保存并退出」保留已发生时长并结束活动计时。完成轮次后可完成任务，重复任务仍经已有完成入口生成后继。

中断统一保留已发生事实；不提供删除已上传记录的丢弃操作。暂不把活动计时同步到其他设备。清缓存、存储不可用或关闭标签页后不保证倒计时恢复；待上传事实仍由独立按账号日志重试。

## 第二阶段已实现：任务版本条件更新

普通任务编辑、完成勾选与 One Thing 取消不再盲目覆盖云端：任务读取时保留 `updated_at` 作为行版本，写入以该版本为条件；成功后把服务端返回的新版本写回本地，连续编辑在同一次会话内可继续通过校验。本地新建、尚未取得版本的任务首次写入不带版本条件，成功后即纳入版本管理。

版本不匹配（其他设备已先修改）时不覆盖云端，提示「检测到其他设备的修改」，并经既有失败恢复通道回读云端最新任务、偏好与通知；本地乐观改动被服务器状态取代，用户可基于最新内容重试。AI 整理沿用并强化同套协议：任务行条件更新成功后同样返回并同步新版本。子任务整组 upsert/清理仍复用普通详情写入流程，暂不参与任务行版本；随后已纳入持久写队列。

## 第二阶段已实现：任务持久写队列

普通任务编辑、完成勾选、子任务整组更新与重复设置进入按账号隔离的 localStorage 队列。同一任务连续输入按最终字段值合并，并保留最早编辑所基于的行版本；刷新后先用待写内容水化服务端快照，再继续上传。标题、描述、日期等普通字段 500ms 防抖；完成状态、子任务、锁定和重复设置立即冲洗；上传失败保留待写内容，进入工作区、网络恢复、页面重新可见或 3 秒重试计时器触发后继续。

上传仍使用 `updated_at` 条件更新。崩溃后若云端已包含同一补丁，可幂等确认；版本不匹配则移除本地待写项，提示冲突并回读云端，不静默覆盖其他设备修改。飞行中产生的新编辑不会被旧确认移除，成功写入会把后续待写条目推进到新的版本世系。完成重复任务后，后继任务回读成功才确认队列条目；回读失败会依赖数据库唯一后继约束重试，不重复生成。

边界保持不变：新建、删除、AI 应用、专注日志与通知仍走既有串行直写，不承诺完整离线；One Thing 因每用户部分唯一索引必须先取消旧值再设置新值，继续走单个有序直写操作。浏览器存储不可用时队列自动降级为本次页面的乐观状态，不阻塞任务编辑。

## 第二阶段已实现：Realtime 多设备同步

工作区为当前账号建立私有 Realtime channel，仅订阅 `tasks`、`subtasks`、`user_preferences`、`notifications` 中 `user_id` 等于当前用户的数据行。事件不直接把增量 payload 写入本地状态，而是在 200ms 内合并成一次完整快照回读；回读进入既有串行队列，等待本地待写上传完成后执行，并继续套用仍未确认的本地待写，避免远端事件覆盖离线编辑。

订阅成功后立即回读一次，补偿订阅建立前错过的变化。`CHANNEL_ERROR`、`TIMED_OUT` 与 `CLOSED` 会移除旧 channel，按 1/2/4/8/15 秒退避重建新订阅；旧 generation 的回调不会再影响当前工作区。卸载或切换账号时清理订阅、去抖与重试计时器，Provider 与 Supabase client 使用同一通道生命周期，避免旧账号订阅残留。顶部工具栏显示连接中、实时同步与重连中状态。

`0008_workspace_realtime.sql` 会创建或复用 `supabase_realtime` publication，把四张工作台表加入 publication 并设置 `replica identity full`。迁移在本地 PostgreSQL 已验证，并已由 CI run #34 部署到目标 Supabase；真实多设备事件、RLS 私有通道与断网重连仍不能视为验收完成。

## 第二阶段已实现：按需读取与服务端搜索

工作区首屏只读取当前账号的未完成任务与上海时区今天完成的任务，不再为了首屏拉取全部旧完成历史。完成页首次进入读取 30 条，使用数据库 exact count 与 range 分页，继续按「加载更多」向后取；恢复或删除时本地同步调整计数。子任务仅按本页任务 ID 批量读取，并附带账号归属条件。

收件箱选中非今天日期时，按该日期向服务端补拉任务；读取按 500 行分页循环，避免超过 PostgREST 默认行数上限后历史日期被截断。加载期间显示日期加载状态。当前日历“有任务”标记仍基于已加载任务，不会预先扫描全部历史日期。

命令面板搜索不再过滤浏览器内存中的全量任务：输入去抖 220ms 后调用 `search_tasks` 数据库函数，匹配标题、描述和标签；每页 30 条，可继续加载。函数以 `auth.uid()` 限制本人数据，在 SQL 内排序、limit 与 offset，并用窗口 count 在 limit 前计算真实匹配总数，避免把本页数量误当作总数。搜索结果会合入客户端任务缓存，选中后仍沿用现有详情抽屉与 `updated_at` 版本协议。

Realtime 或失败恢复回读时，基础快照仍为未完成任务加今天完成项；已经加载的历史完成项会按 ID 补充重取，避免旧历史页被基础快照挤掉或保留远端已删除/更新的旧副本。读取也经过串行队列，先等待本地待写上传，再套用仍未确认的待写内容。

`0009_task_search.sql` 新增搜索函数与 authenticated 执行权限；Supabase 环境存在 `extensions` schema 时创建标题、描述 trigram 索引，本地 PGlite 无该 schema 时跳过索引但验证函数行为。该迁移已由 CI run #34 部署到目标 Supabase；真实 trigram 索引、RPC 响应与大结果分页仍不能视为验收完成。

## 第三阶段已实现：统计与成长事实

Insights 从数据库 RPC 聚合本人任务与专注事实，展示月度专注、每日目标、任务打卡、预估 vs 实际耗时、清单分布、未关联专注和 42 天热力图。日期边界使用账户时区，跨月归属由 SQL 测试用 `Pacific/Kiritimati` 与 `Pacific/Honolulu` 的自然月界验证；统计读取失败直接抛给页面错误边界，不再伪装为零。

成长体系新增 `growth_events` / `growth_plants`：每 120 分钟专注生成一个永久植物，成就、XP 和金币由不可变事件表累计，重复加载或重试使用事件键幂等去重。关闭游戏化偏好后不再同步或展示奖励。连续天数按账户时区计算，专项测试覆盖奖励不重复、种植时间等于事实时间、客户端对奖励表只读。

## 第三阶段已实现：账号、通知与偏好

设置页提供本人数据导出与删除账号。导出走登录会话与 RLS 读取任务、子任务、偏好、通知、专注、语音、成长数据，不导出 Auth 凭据；删除必须输入当前邮箱确认，POST 同源校验后由服务端 service role 调 Auth 删除，业务表随 Auth 用户级联清理，审计表仅保留用户 ID、时间与结果且对 authenticated 不可读。语音隐私面板支持查看最近 50 条转写、单删、清空与热词维护；转写服务端会读取热词，原始音频仍不落库。

通知支持默认提前量、每日摘要、1–90 天保留期与账户开关。保留期到期物理删除旧通知；清空仍只是持久隐藏。任务提醒去重键从“任务终身一条”改为“任务 + 提醒时间”，同一时间并发补扫不重复，改期后的下一次提醒可以生成，旧提醒不会因清空或回访重生。站内通知仍不申请系统权限、不做后台 Web Push 或邮件送达。

时区与小时制保存在 `user_preferences`，时区必须是有效 IANA 名称，默认上海且不跟随设备。今日、收件箱、日历、详情、完成页、提醒、每日摘要边界、语音解析的“今天/现在”、重复任务后继日期和统计 RPC 均使用同一账户时区；切换偏好只影响展示与日期推导，不重写任务事实。

## 第三阶段已实现：AI 顾问与语音 M3

Insights 增加独立 AI 顾问入口，输入当天未完成任务与最近专注事实，服务端校验登录、同源、请求体、配额和模型输出。建议覆盖子任务、独立预估、容量判断与周回顾；界面可勾选、编辑、取消后应用。应用只写勾选任务的 `estimate` 和原本没有子任务任务的新子任务，不修改标题、日期或时间，也不调用当日整理。

语音录制连续静音 4 秒自动停止；页面切到后台立即结束采集并编码已录片段，仍走确认上传流程。权限拒绝、无设备、设备占用、采集失败、网络失败、上游失败、超时和限流分别映射为明确错误；本地回归覆盖静音累计/重置与错误矩阵。手动停止与 Safari/iOS 真实麦克风、后台切换验收仍未执行。

`0010_insights_growth_notifications.sql` 与 `0011_account_and_date_preferences.sql` 均为新增待部署迁移。专项 PGlite 测试从 `0001` 执行到 `0011`，覆盖全量迁移、IANA 时区校验、月界统计、奖励幂等、通知改期去重、账号审计隐私、Auth 用户级联删除、语音历史/热词 RLS 与导出服务边界。
