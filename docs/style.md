# DiDa-todo 界面设计规范

> 版本：1.0 · 更新：2026-09-09  
> 适用范围：首页、登录／注册弹窗，以及后续 Todo、Planning、Focus 等 Web 界面。  
> 设计基线：奶油白底、深炭黑文字、香槟金点缀、衬线标题、细边框、轻阴影。

## 1. 使用方式与依据

开发新界面前先阅读本文件，复用现有设计变量和组件。本文的「当前」描述已经落地的样式；「后续约定」用于指导尚未实现的界面，不表示对应功能已经完成。

| 来源                                                                   | 负责内容                                     |
| ---------------------------------------------------------------------- | -------------------------------------------- |
| [globals.css](../src/styles/globals.css)                               | 颜色、字体、圆角、全局焦点和减少动态效果规则 |
| [landing.module.css](../src/features/landing/landing.module.css)       | 首页布局、按钮、展示卡片、响应式细节         |
| [auth-dialog.module.css](../src/features/auth/auth-dialog.module.css)  | 登录／注册弹窗、表单、Tabs、动效             |
| [auth-dialog.tsx](../src/features/auth/auth-dialog.tsx)                | 弹窗触发、切换、关闭和焦点恢复               |
| [原始首页](reference/index.html)、[原始登录弹窗](reference/login.html) | 初始视觉参考，保留原文件，不作为生产页面加载 |

本文维护的是设计意图和复用规则，不要求复制 CSS 中的重复声明或选择器错误。涉及尺寸时同时检查组件的实际调用及响应式覆盖。后续主动调整公共设计，应同步更新本文、变量及受影响组件，避免多个页面各自保留一套规则。

## 2. 视觉方向

整体感觉应当安静、明亮、温暖，有清晰的排版层次。通过空间、字重、细线和表面颜色区分内容，金色只强调少量重点。

- **页面底色温暖，内容表面干净。** 大面积奶油白背景搭配纯白卡片。
- **标题有编辑感，操作区重视清晰。** 衬线字体承担品牌、展示标题和少量关键数字；正文与控件使用无衬线字体。
- **边缘简洁。** 以直角和小圆角为主，避免把按钮、卡片、标签全部改成胶囊或大圆角。
- **层次轻。** 使用 1px 边框和低透明度阴影，只有导航、展示工作台和弹窗遮罩采用毛玻璃。
- **动效克制。** 反馈短暂，位移很小，不让装饰动画干扰任务操作。

品牌名称统一使用 **DiDa-todo**，中文延续「滴滴待办」。原参考中的 `DiDi-todo` 不再用于新增文案。

## 3. 色彩与语义变量

### 3.1 当前浅色主题

新增组件优先引用 CSS 变量或对应 Tailwind 语义类，避免在功能文件中重复定义主色。

| CSS 变量                                         | 当前值    | 用途／Tailwind 示例                          |
| ------------------------------------------------ | --------- | -------------------------------------------- |
| `--background`                                   | `#FAF7F2` | 页面背景，`bg-background`                    |
| `--foreground`                                   | `#1C1917` | 主文字、实心主按钮背景，`text-foreground`    |
| `--card` / `--popover`                           | `#FFFFFF` | 卡片、弹窗内容、浮层表面                     |
| `--card-foreground` / `--popover-foreground`     | `#1C1917` | 对应表面上的主文字                           |
| `--brand-gold`                                   | `#B88E57` | 品牌强调、悬停、优先级装饰                   |
| `--primary`                                      | `#B88E57` | 基础组件主色变量；不直接等同于首页主按钮配方 |
| `--primary-foreground`                           | `#FFFFFF` | 主色表面文字；实际使用仍需检查可读性         |
| `--secondary` / `--muted` / `--accent`           | `#F3EEE6` | 浅暖色辅助表面、轻选中背景                   |
| `--secondary-foreground` / `--accent-foreground` | `#65513B` | 辅助表面上的文字                             |
| `--muted-foreground`                             | `#78716C` | 次要说明、日期、辅助操作                     |
| `--border` / `--input`                           | `#E7E5DF` | 卡片边框、分隔线、输入框底线                 |
| `--ring`                                         | `#B88E57` | 键盘焦点和输入焦点                           |
| `--destructive`                                  | `#C52E37` | 删除、错误等语义，不作品牌装饰               |

**两点必须区分：**

1. `--accent` 是浅暖色背景，品牌金色使用 `--brand-gold`。原始 HTML 把金色命名为 `--accent`，不能照搬到当前项目。
2. 当前主按钮是深炭黑底，悬停才变为金色。直接使用 shadcn 默认 `bg-primary` 会变成常驻金色，不能视为已匹配当前按钮样式。现有 `.btnGold` 名称也不表示默认金色背景。

### 3.2 透明表面与边线

| 场景           | 当前配方                                    |
| -------------- | ------------------------------------------- |
| 固定导航       | `rgba(250, 247, 242, 0.8)`，背景模糊 `15px` |
| 首页任务展示卡 | `rgba(255, 255, 255, 0.6)`，背景模糊 `25px` |
| 展示卡高光边框 | `1px solid rgba(255, 255, 255, 0.8)`        |
| 弹窗遮罩       | `rgba(250, 247, 242, 0.7)`，背景模糊 `12px` |
| 轻分隔线       | 黑色 `4%–5%` 透明度，宽度 `1px`             |
| 金色标签       | 文字品牌金；金色 `30%` 边框、`5%` 背景      |
| 展示卡背景光   | 金色 `12%` 径向渐变，向透明渐隐             |

渐变只用于首页展示卡附近的柔光，不扩展成全站彩色渐变背景。模糊不可用时，也应依靠表面颜色和边框保持内容清晰。

### 3.3 暗色与业务状态边界

当前设计基线仅为浅色。`globals.css` 中已有 `.dark` 的深蓝／浅蓝变量，是基础框架预留值，**没有形成与当前风格统一的暗色设计，也没有主题切换功能**。不要直接启用后宣称暗色适配完成。

成功、警告、任务多级优先级、图表系列色尚未形成完整规范。后续需要时按语义补充统一变量，并同步本文；不要把品牌金当成所有状态的通用颜色，也不要只靠颜色传达状态。

## 4. 字体与排版

### 4.1 字体职责

| 变量           | 字体栈                                                          | 使用场景                                   |
| -------------- | --------------------------------------------------------------- | ------------------------------------------ |
| `--font-serif` | `Playfair Display`, `Songti SC`, `SimSun`, serif                | 品牌、Hero、展示区标题、弹窗标题、展示数字 |
| `--font-sans`  | `Inter`, 系统字体、`PingFang SC`, `Microsoft YaHei`, sans-serif | 正文、任务标题、表单、按钮、导航           |
| 当前任务时间   | monospace                                                       | 简短时间段，保持数字辨识度                 |

字体通过 `@fontsource` 在根布局中本地加载。Inter 当前加载 300／400／500／600；Playfair Display 加载 400、400 italic、700。Playfair 不包含中文字符，中文由字体栈中的中文字体回退显示。

不要额外引入无关字体；新增字重前检查是否已加载。不要对整段中文正文增加大字距或使用斜体。

### 4.2 已实现的排版尺度

下表按浏览器默认 `1rem = 16px` 换算；保留用户调整根字号的能力。

| 元素           | 桌面尺寸              | 字重／行高／其他                         |
| -------------- | --------------------- | ---------------------------------------- |
| Logo           | `26px`                | serif，700，字距 `1px`                   |
| Hero 主标题    | `4.5rem`（72px）      | serif，400，行高 1.1；强调片段用灰色斜体 |
| 区块标题       | `2.5rem`（40px）      | serif，400                               |
| 成长介绍标题   | `3rem`（48px）        | serif，400，行高 1.2                     |
| 底部 CTA 标题  | `3.5rem`（56px）      | serif，400                               |
| 弹窗标题       | `2rem`（32px）        | serif，400，行高 1.25                    |
| Today 展示标题 | `1.5rem`（24px）      | serif                                    |
| Hero 描述      | `1.1rem`（约 17.6px） | sans，300，最大宽度 `450px`              |
| 全局正文       | `1rem`（16px）        | sans；首页行高 1.6                       |
| 功能卡标题     | `16px`                | sans，600                                |
| 任务标题       | `14px`                | sans，500                                |
| 输入内容       | `14px`                | 窄屏登录弹窗提升到 `16px`                |
| 导航、表单描述 | `13px`                | 导航英文大写、字距 `2px`                 |
| 常规按钮       | `12px`                | 英文大写、字距 `2px`，实心按钮 600       |
| 顶部英文短标签 | `12px`                | 大写、字距 `6px`，窄屏缩至 `4px`         |

**后续约定：** 新增工作台正文以 `16px` 为默认，常用控件和任务信息以 `14–16px` 为起点，页面标题可使用 `24–32px` 衬线字体。展示首页现有的 9–12px 标签、时间和辅助文字属于紧凑参考细节，不应推广为整个产品的小字号标准。错误提示、截止时间等关键信息需要足够醒目。

## 5. 布局、留白与密度

### 5.1 首页当前布局

| 项目           | 当前值                                         |
| -------------- | ---------------------------------------------- |
| 主容器         | 最大宽度 `1280px`，居中，基础左右内边距 `40px` |
| 顶栏           | 固定顶部，桌面内边距 `25px 40px`               |
| Hero           | 桌面最小高度 `100vh`，顶部内边距 `80px`        |
| Hero 网格      | `1fr 1fr`，列间距 `60px`                       |
| 功能卡         | 桌面 4 列，间距 `30px`                         |
| 成长区         | `1fr 1.2fr`，列间距 `80px`                     |
| 成长小卡       | 3 列，间距 `20px`                              |
| 评价区         | 3 列，间距 `30px`                              |
| 展示区纵向留白 | 常用 `100px`、`120px`；窄屏降为 `80px`         |

当前基础容器和区块 padding 存在分别覆盖的情况；新增页面应明确保留外层左右安全边距，避免一个 `padding: 120px 0` 意外清除容器留白。

### 5.2 后续页面的间距约定

优先从 `4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 60 / 80 / 120px` 中选择间距。现有参考里的 `15 / 25 / 30 / 35 / 50px` 是特定组件的精确配方，复用这些组件时保留，不需要为了凑刻度改动视觉。

- 字段、图标与文字之间保持紧密关系，常用 `8–12px`。
- 控件组和卡片内部常用 `16–24px`，展示卡可以增加到 `30–40px`。
- 页面主区与相邻内容之间保持明确留白，避免为每一行增加独立卡片。
- Todo 工作台以任务操作为中心，使用紧凑列表和清晰分区；沿用字体、颜色、细线与按钮规则即可，不复制首页的全屏 Hero、宣传指标和大段留白。

## 6. 边框、圆角、阴影与图标

### 6.1 边框和圆角

普通边框使用 `1px solid var(--border)`。按钮、功能卡和登录卡以直角为主；任务展示卡为 `4px`，任务复选框为 `2px`。

全局 `--radius = 0.25rem`，在默认字号下：`rounded-sm = 0px`、`rounded-md = 2px`、`rounded-lg = 4px`、`rounded-xl = 8px`。不把 shadcn 通用示例里的大圆角原样带入新页面。

### 6.2 当前阴影配方

| 表面       | 阴影                              |
| ---------- | --------------------------------- |
| 任务展示卡 | `0 30px 60px rgba(0, 0, 0, 0.04)` |
| 功能卡     | `0 10px 30px rgba(0, 0, 0, 0.02)` |
| 成长小卡   | `0 10px 20px rgba(0, 0, 0, 0.02)` |
| 登录弹窗   | `0 20px 40px rgba(0, 0, 0, 0.03)` |

阴影只辅助区分层次，避免浓重黑影、彩色发光和多层浮雕效果。普通任务列表不需要逐行阴影。

### 6.3 图标

统一使用 Lucide 线性图标，常用 `16–24px`，当前展示图标描边约 `1.25–1.5`，关闭图标为 `22px / stroke 1`。品牌标记是 `16px` 空心金色方形旋转 45°，边框 `2px`，复用 `Brand` 组件。

装饰图标标记 `aria-hidden`，只有图标的按钮提供可读名称。图标尺寸与可点击区域分开设置；当前关闭和加号按钮区域为 `36px`，后续高频触控操作应提供更宽裕的点击区域。

## 7. 组件配方

### 7.1 按钮与链接

| 类型         | 默认                          | Hover          | 尺寸与文字                              |
| ------------ | ----------------------------- | -------------- | --------------------------------------- |
| 实心主按钮   | 炭黑底、白字、炭黑 1px 边框   | 金色背景与边框 | 常规 padding `10px 28px`，最小高 `42px` |
| 描边次按钮   | 透明底、炭黑字、暖灰 1px 边框 | 边框变炭黑     | 与常规按钮同一排版尺度                  |
| 表单提交     | 炭黑底、白字，占满表单宽度    | 金色背景与边框 | padding `14px 0`，顶部间距 `10px`       |
| 辅助文本操作 | 暖灰文字，无填充背景          | 金色文字       | 低于主操作的视觉权重                    |

Hero CTA 为 `15px 35px`；底部 CTA 为 `16px 45px`，字号 `14px`。这些扩大尺寸仅用于展示页。

后续禁用态应同时具备不可交互语义和可识别外观，取消 hover 强调；加载态保留按钮宽度与动作名称，阻止重复提交。当前尚无统一 loading／disabled 按钮封装，新增时集中定义。

### 7.2 表单

- 登录／注册表单使用下划线输入风格：透明背景，仅底部 `1px` 暖灰线，不套厚重圆角框。
- 输入上下 padding `10px`；字段组底部间距 `25px`；标签与输入间距 `5px`。
- 当前英文标签 `10px`、字距 `2px`、大写；这是登录参考配方。新增业务表单标签优先保证可读性，不强制套用小字号。
- 聚焦时底线变金色，并增加 `0 1px 0` 金色阴影。只有提供等效可见焦点反馈时，才可取消默认 outline。
- Placeholder 当前为 `#B5AFA6`、300 字重，只提供示例，不替代与输入关联的 label。
- 错误信息放在对应字段附近，使用错误语义色和文字；不要只把边框改红。
- 密码和邮箱使用正确的 `type`、`autoComplete` 与 label 关联，避免仅靠视觉模拟表单。

当前密码字段来自视觉参考；本文不决定最终认证方案，实际认证仍按技术栈与产品要求实施。

### 7.3 登录／注册弹窗

弹窗覆盖在当前页面上，不跳转到独立登录路由。复用 `AuthDialogProvider` 和 `AuthTrigger`，底层使用 shadcn／Radix Dialog。

| 属性     | 当前规范                                           |
| -------- | -------------------------------------------------- |
| 内容宽度 | `calc(100% - 32px)`，最大 `440px`                  |
| 内容高度 | 最大 `calc(100dvh - 32px)`，内容超出时内部纵向滚动 |
| 内边距   | `40px 40px 50px`；≤480px 时为 `36px 24px`          |
| 内容表面 | 纯白、直角、黑色 4% 的 1px 边框、轻阴影            |
| 遮罩     | 奶油白 70%，模糊 12px                              |
| 层级     | 遮罩 1000、内容 1001；导航 100                     |
| 关闭入口 | 右上角细线 X、点击遮罩、Esc                        |
| 焦点     | 限制在弹窗内部；关闭后返回触发按钮                 |

不要用黑色高不透明度遮罩覆盖当前奶油色磨砂风格。后续宽表单可在明确内容需要时增加宽度，但保持相同表面和交互规则。

### 7.4 登录／注册 Tabs

左对齐，Tab 间距 `20px`，整个栏底部为暖灰 `1px` 线。激活项使用炭黑字、600 字重和炭黑底线，无胶囊背景、填充色块或阴影。当前 Tab 下内边距 `10px`，栏下间距 `30px`。

复用 Radix Tabs 的键盘和语义行为；不要只给两个普通按钮切换颜色来模拟 Tabs。

### 7.5 任务行、标签与卡片

任务行横向排列复选框、标题／时间、右侧标签；当前纵向 padding `16px`、元素间距 `15px`，使用很淡的底部分隔线，最后一项不加底线。完成状态为复选框选中、标题删除线和次要文字色，不隐藏任务文字。

普通标签透明底、1px 暖灰边框，当前 padding `3px 8px`；重要标签才使用淡金色表面。后续任务优先级应具有文字或图标含义，不把标签色彩当作纯装饰。

功能展示卡可以居中排版；任务、设置与数据详情以左对齐为主。后续工作台卡片优先纯白表面，毛玻璃任务预览不直接等同于实际任务列表容器。

## 8. 动效与交互状态

| 场景               | 当前表现                                                                  |
| ------------------ | ------------------------------------------------------------------------- |
| 按钮、边框变色     | 约 `0.3–0.4s`                                                             |
| 功能卡 Hover       | 上移 `5px`，边框变金                                                      |
| 任务预览行 Hover   | 右移 `5px`                                                                |
| 弹窗进入           | `0.35s`，透明度进入、纵向 20px 位移；缓动 `cubic-bezier(0.16, 1, 0.3, 1)` |
| 遮罩／表单视图进入 | `0.3s` 淡入                                                               |
| 关闭按钮 Hover     | 旋转 90°，颜色加深                                                        |

新增动效优先显式声明 `color`、`background-color`、`border-color`、`opacity`、`transform`，不照搬现有展示样式中的 `transition: all`。高频任务操作可以用背景或边线反馈，避免每次移动行内容。

遵守现有 `prefers-reduced-motion` 规则。关闭态动画尚无专门视觉配方，不把进入动画反复套到所有状态上。

## 9. 响应式规则

断点以现有 CSS Modules 为准，不默认套用 Tailwind 自带断点替换当前布局。

| 宽度       | 当前变化                                                                                       |
| ---------- | ---------------------------------------------------------------------------------------------- |
| >1150px    | 完整桌面布局，Hero 双列、功能四列                                                              |
| 901–1150px | Hero 标题 60px、列间距 32px；导航和成长区收紧间距                                              |
| ≤900px     | Hero／成长主区单列、主导航链接隐藏；功能卡两列、成长小卡三列、评价单列；展示区纵向间距 80px    |
| ≤600px     | 主容器左右 24px；Logo 22px；隐藏顶部 Start Now、保留 Log In；功能与成长卡单列；Hero 顶部 135px |
| ≤480px     | 登录卡 padding `36px 24px`，输入字号 16px                                                      |

≤900px 的 Hero 标题使用 `clamp(2.5rem, 7vw, 3.5rem)`。手机上不简单等比缩小桌面 UI，应调整列数、内容顺序和留白；长标题允许换行，表单允许滚动，不能靠全局隐藏横向溢出来遮住布局问题。

后续应用导航可以收起为抽屉，但不能像展示首页一样直接隐藏用户完成任务必须使用的导航。文字放大与窄屏状态下仍需保持核心操作可达。

## 10. 工程落地规则

- 全局主题只维护在 `src/styles/globals.css`；功能细节放在 `features/<domain>/*.module.css`。
- shadcn／Radix 提供基础行为与无障碍能力；在调用处通过类名和语义变量匹配项目视觉，不直接接受组件默认配色、圆角和阴影。
- 跨功能反复使用的按钮、表单或卡片应抽成共享组件；尚未复用的展示细节保留在功能模块，避免提前创建庞大组件库。
- 页面主体保持 Server Component；状态、事件、弹窗与浏览器行为放在小范围 Client Component 内。
- CSS Modules 覆盖基础样式时使用明确、可控的选择器，不给整个项目追加宽泛的 `button`、`input`、`h2` 业务规则。
- 不把原始 HTML 放进 iframe，不导入其 `<style>` 或脚本替代 React 组件，也不把展示 mockup 当作真实数据功能。

## 11. 避免的风格偏移

| 不采用的变化                               | 应保持的方向                         |
| ------------------------------------------ | ------------------------------------ |
| 亮蓝主按钮、紫色大渐变、霓虹强调           | 炭黑主操作、香槟金少量反馈           |
| 大圆角卡片和胶囊按钮铺满页面               | 直角、小圆角、细边框                 |
| 所有卡片都使用重阴影、毛玻璃               | 白色平静表面，仅特定层次使用玻璃效果 |
| 全站统一粗体无衬线标题，或所有正文都用衬线 | 展示标题 serif，操作与正文 sans      |
| 在工作台复制首页大标题与宣传留白           | 用任务列表和明确操作组织信息         |
| 把小号大写英文和大字距套到所有标签         | 展示标签保留风格，业务信息优先易读   |
| 只检查页面截图，不验证按钮和键盘操作       | 同时检查视觉、焦点、弹窗与状态反馈   |
| 把现有深蓝 `.dark` 当成完整品牌暗色主题    | 暗色单独设计并验证后再启用           |
